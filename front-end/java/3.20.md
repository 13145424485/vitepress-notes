HashMap 和 ConcurrentHashMap 的核心区别？
HashMap 线程不安全；ConcurrentHashMap 通过更细粒度并发控制提升多线程性能，适合高并发读写场景。

Java 里怎么避免共享可变状态带来的并发问题？
优先不可变对象、局部变量、消息传递；实在要共享时再用锁、原子类或并发容器。



线程池 7 参数和执行流程是什么？ 追问：为什么不推荐直接用 Executors？CallerRunsPolicy 有什么影响？

7 参数是 corePoolSize、maximumPoolSize、keepAliveTime、unit、workQueue、threadFactory、RejectedExecutionHandler；

执行流程是“核心线程没满先建线程，满了先进队列，队列满了再建非核心线程，再满就走拒绝策略”；

Executors.newFixedThreadPool() 用无界队列，newCachedThreadPool() 线程数可能失控；

CallerRunsPolicy 会让提交任务的线程自己执行任务，形成反压，但会拖慢调用方。





线程池的拒绝策略有哪些，分别适合什么场景？ 追问：你们项目里的 AI 线程池为什么可能选 CallerRunsPolicy？

答案：AbortPolicy 直接抛异常；CallerRunsPolicy 调用方自己执行；DiscardPolicy 直接丢弃；DiscardOldestPolicy 丢最旧任务再尝试提交

。在线业务一般不能默默丢任务，更多会选抛错或反压；AI 任务如果允许变慢但不能无限堆积，CallerRunsPolicy 是可接受的。Google：Java 线程池 拒绝策略 CallerRunsPolicy 面试



Spring 的 IoC 和 AOP 分别是什么？ 追问：单例 Bean 一定线程安全吗？

答案：IoC 是控制反转，核心是对象创建和依赖注入交给容器；AOP 是面向切面，把事务、日志、权限这类横切逻辑统一织入。

单例 Bean 只是“一个容器里一个实例”，不等于线程安全；无状态 Bean 通常安全，有成员变量保存请求状态就可能不安全。



Bean 生命周期/ioc流程大致说一下。 追问：常见作用域有哪些？

答案：实例化、属性注入、Aware 回调、初始化前后处理、init、正常使用、销毁；

默认作用域是 singleton，常见还有 prototype、request、session、application、websocket。



@Transactional 的底层原理和默认行为是什么？追问：默认回滚哪些异常？

本质也是 AOP 代理，代理里通过TransactionInterceptor配合TransactionManager开启、提交、回滚事务；默认传播行为是REQUIRED，隔离级别跟数据库默认走，默认只对 RuntimeException和Error 回滚，受检异常默认不回滚。



数据库事务的 ACID 和四种隔离级别说一下。 追问：脏读、不可重复读、幻读分别是什么？

ACID 是原子性、一致性、隔离性、持久性；四种隔离级别是 READ UNCOMMITTED、READ COMMITTED、REPEATABLE READ、SERIALIZABLE

脏读是读到未提交数据，不可重复读是同一行前后读结果不同，幻读是范围查询前后行数变化。

MySQL 的 MVCC 是什么？ 追问：InnoDB 默认隔离级别是什么？

答案：MVCC 是多版本并发控制，通过版本链和快照读减少读写冲突；普通查询很多时候是非锁定一致性读。InnoDB 默认隔离级别是 REPEATABLE READ。



MyBatis 一级缓存和二级缓存说一下。

MyBatis 一级缓存是**SqlSession 级别**的默认缓存，同一会话内**相同查询会直接命**中，执行增删改或清空缓存时失效，打开一个数据库连接，查了一遍用户信息，它就记下来，再查一次直接给你，不用再查库。**一关连接就清空，别人也看不到。**

；二级缓存是**Mapper 级别**的全局缓存，需手动开启，可跨会话**共享查询结果**，要求实体类序列化，同样会在执行增删改后清空，查询时会先查二级缓存，再查一级缓存，最后查询数据库。只要是查同一张表的所有人，不管谁查的，结果都放这里共享。**只要没人改数据，大家都能直接用；一有人增删改，整块黑板擦掉重写。**



MySQL 索引为什么常说是 B+ 树？ 追问：为什么不用哈希或红黑树？

答案：面试里一般回答 B+ 树，因为它层高低、磁盘 IO 少、叶子节点有序、范围查询和排序友好。哈希**适合等值查询不适合范围**；红黑树在磁盘场景层高太高。

联合索引、最左前缀、覆盖索引是什么？ 追问：索引什么时候容易“失效”？

答案：联合索引是多个列组成一个索引；最左前缀是 (a,b,c) 可以用在 (a)、(a,b)、(a,b,c)；覆盖索引是查询所需列都在索引里，不用回表。

常见用不上索引的情况有前导模糊 %xx、对索引列做函数/计算、隐式类型转换、没有命中最左列。

慢 SQL 怎么排查？EXPLAIN 重点看哪些字段？ 追问：type、key、rows、Extra 分别怎么看？答案：先看慢日志，再用 EXPLAIN；重点看有没有命中索引、扫描行数是不是过大、有没有临时表和文件排序。key 看实际用了哪个索引，rows 看预估扫描量，type 越接近 const/ref/range 越好，ALL 往往表示全表扫，Extra 里如果有 Using filesort、Using temporary 就要警惕。Google：慢SQL 排查 EXPLAIN key rows extra 面试

Redis 为什么快？ 追问：是不是因为“单线程所以快”

核心原因是数据在内存、数据结构高效、命令执行路径短、网络层用 I/O 多路复用。单线程只是它避免了大量锁竞争和上下文切换，不是唯一原因。

Redis 常见数据结构及使用场景。 追问：String、Hash、List、Set、ZSet 怎么选？答案：String 适合缓存、token、计数器；Hash 适合对象字段；List 适合简单队列；Set 适合去重；ZSet 适合排行榜、延时任务。面试时把“结构 + 一个典型场景”说出来就够。

Redis 持久化 RDB 和 AOF 的区别。 追问：线上怎么选？

RDB 是定时快照，适合备份、恢复快，但可能丢最近几分钟数据；AOF 是追加写日志，更耐丢数据，但文件更大、恢复可能更慢。很多线上会两者都开，兼顾恢复速度和数据安全。

缓存穿透、击穿、雪崩分别是什么，怎么解决？ 追问：热点 key 过期怎么办

：穿透是查不存在的数据，解决思路是空值缓存、布隆过滤器；击穿是热点 key 失效瞬间大量请求打 DB，解决思路是互斥锁、逻辑过期、后台重建；雪崩是大量 key 同时失效或 Redis 整体不可用，解决思路是过期时间打散、多级缓存、限流降级。

热点 key 过期最常见做法是互斥重建或逻辑过期。



登录态和实时推送怎么设计？ 追问：Session、JWT、Redis Token 怎么选？WebSocket、SSE、长轮询怎么选？答案：Session/Redis Token 是有状态方案，便于失效、踢下线、风控；JWT 是无状态方案，扩容方便，但撤销麻烦。实时通信里 WebSocket 适合双向低延迟，SSE 适合服务端单向推送，长轮询最简单但效率最低；

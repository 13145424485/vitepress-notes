## 1.知道微服务吗？微服务的好处和坏处？



微服务就是把一个大系统**拆成**多个小服务，每个服务**负责自己明确的一块业务**，通过接口互相调用。
好处是拆分后**职责更清晰**，团队可以并行开发，单个服务也更容易独立扩容和发布。
坏处也很明显，系统会变复杂，服务之间调用链更长，部署、监控、容错、分布式事务这些问题都会出来。





# **分布式**

##  雪花算法具体怎么生成一个全局唯一 ID 呢？

雪花算法本质上是把一个 64 位整数拆成几段来用，常见就是**时间戳、机器标识和序列号**。时间戳保证整体递增趋势，机器标识保证不同机器生成时不冲突，序列号保证同一台机器在同一毫秒内能生成多个 ID。这样拼起来之后，只要机器号不重复、时钟不乱跳，整体就能保证全局唯一，而且趋势递增，比较适合数据库主键和分布式场景。这个项目里发帖草稿 ID 就是这么生成的，它的好处就是不依赖数据库自增，不容易成为单点瓶颈。

##  想要唯一 ID 还有其他方法吗？

常见的有几类。第一是 UUID，优点是简单、无中心化，但太长、无序，不太适合数据库索引；

第二是数据库自增 ID，简单但扩展性差，容易成为瓶颈；

第三是号段模式，比如一次从数据库拿一批 ID，在本地慢慢发；

第四就是雪花算法这种本地生成的分布式 ID。

## 为什么不直接用 UUID，数据库能保证分库分表的唯一 ID 吗？

 不直接用 UUID，主要是因为它太长、无序，对数据库索引不友好，插入时容易造成索引页分裂，查询和存储成本也更高。数据库当然能通过主键约束保证单表唯一，理论上也可以在分库分表场景下通过库号、表号、自增步长这些方式拼出唯一 ID，但这种方案强依赖数据库，扩展和迁移没那么灵活。
